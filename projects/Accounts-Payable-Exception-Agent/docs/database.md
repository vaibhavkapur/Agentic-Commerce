# Database

[Documentation](index.md) · [Getting Started](getting-started.md) · [Repository README](../README.md)

Core entities: `organizations`, `memberships`, `vendors`, `beneficiaries`, `cases`, `document_versions`, `extracted_fields`, `evidence_links`, `exceptions`, `approval_requests`, `approval_decisions`, `payment_instructions`, `agent_runs`, and `audit_events`.

Every business record belongs to an organization. Row Level Security must restrict frontend reads to permitted memberships. Privileged backend connections must perform explicit tenant and role checks; using Supabase does not make those checks automatic.

An approval binds to a canonical snapshot hash containing:

- Organization and case identifiers.
- Invoice identifiers and document-version hashes.
- Amount and currency.
- Approved beneficiary identifier and version.
- Resolved exception decisions and evidence references.
- Approval-policy version and expiry.

A relevant document, amount, beneficiary, or policy change invalidates the approval. Bank details extracted from an invoice cannot update the vendor register. A changed beneficiary blocks export until the administrator's verification process is complete and the case is reviewed again.

Export creation must be idempotent. Repeating an export request for the same approved snapshot returns the original instruction; it must not create another payable obligation.

## Schema and Persistence

[SQLAlchemy models](../backend/app/models.py) define the current entities. The local database is `backend/data/ap.db`; uploads and generated demo PDFs also live under `backend/data/`. LangGraph checkpoints use `backend/data/checkpoints.sqlite` by default. These are local runtime files and are excluded from Git.

[0001_initial.sql](../backend/supabase/migrations/0001_initial.sql) contains the PostgreSQL schema generated by [export_schema.py](../backend/scripts/export_schema.py). Back up application records, files, and checkpoints together. The local SQLite checkpoint store remains separate even when application records use PostgreSQL.
